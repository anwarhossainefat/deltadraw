    Grammar → PDA

    Sipser's construction (Lemma 2.21): the PDA keeps the leftover part of a leftmost derivation on its stack. It replaces a variable on top with a right side of one of its rules, and matches terminals on top against the input.

      Draw and simulate pushdown automata

      A pushdown automaton is an NFA with a stack (Sipser, Chapter 2.2). Draw one with Sipser's labels, run strings through it and watch the stack change step by step, read off its formal definition, and build a PDA from any context-free grammar.

      How a PDA runs

      1. It starts in the start state with an empty stack.
      2. A rule a,b→c can be used when the next input symbol is a (or a is ε) and b is on top of the stack (or b is ε).
      3. The PDA is nondeterministic: it accepts when some branch reads the whole input and is then in an accepting state. The stack does not have to be empty.
      4. Test finds the shortest accepting computation and steps through it with the stack drawn beside it.

      Drawing

      1. Double-click to add a state, and Shift + drag (or the Transition tool) to add an arrow.
      2. Select an arrow and type its rules. Use ; new rule to stack another rule on the same arrow.
      3. Export as PNG, SVG, LaTeX (TikZ) or JFLAP. JFLAP starts its PDAs with Z on the stack; DeltaDraw follows Sipser and starts with an empty stack.
